## 工程难点与处理

**数据源权限与展示语义。** 免费数据源能返回历史日线，但没有分钟和实时能力。按能力控制图表布局，根据接口来源区分最近收盘与实时行情，避免把历史快照呈现为实时结果。

**存储、数据库视图与内存缓存一致性。** 新导入分区文件后，仅刷新缓存不足以让原先不存在的指数视图可查询。补数脚本复用原仓库写入方法，按顺序刷新视图和缓存，再检查指数接口的来源及返回数量。

**可重复执行与进程边界。** 对同一数据快照、策略参数和成本配置分别调用原版服务与 HTTP 回测 worker，逐项比较交易明细和净值序列；用来源哈希、固定提交及参数记录限定结果的可复现条件。

**金融数据的时间与口径。** 识别财报报告期与公告日期不同、旧报告可能被修订，以及累计口径、币种单位、复权因子权限等问题；当前保留财报采集结果，尚未将未经核验的财务或行业字段接入策略。

## 简历表述

**研衡量化金融数据分析与策略验证系统的设计与开发｜开源二次开发项目。**

**项目内容：** 面向 A 股与 ETF 数据研究需求，基于开源量化应用开展前后端适配和公开数据验证，以半导体标的为首批样本，将行情查看、技术指标、策略运行与历史回测串联。

**关键技术：** React / TypeScript、Python / FastAPI、Polars / DuckDB、数据归一化与溯源、策略回测、接口与进程执行一致性验证。

**个人贡献：** 完成开源系统部署与品牌适配，编写公开行情和财报采集校验脚本，保留来源、时间和数据哈希；基于原有引擎构建均线策略验证流程，核对直接调用与 HTTP 子进程回测结果；处理指数数据缺失及数据库视图与缓存刷新问题，完善免费数据源下的展示和异常提示；整理验证报告、复现步骤与功能边界。

**项目价值：** 建立从公开样本采集到策略执行和结果核验的工程流程，提高数据状态和实验过程的可追溯性，为后续多行业指标研究及策略共享功能提供基础。
